## 1. 现状要点（调研结论）

本地实测（headless Chromium，iPhone 390×844 视口）：

- 直接打开本地 HTML：`load` 2.42 s，图标全部生成完成 2.47 s；637 张卡片全部以 `dataURL` 写入 DOM，`img.src` 字符串合计约 **4.08 MB**。
- 线上（无节流，本机网络）：TTFB 316 ms，但正文下载耗时 **4.7 s**（传输 1.55 MB gzip，解压 2.89 MB），DOM 可交互约 7.1 s；整页只有 1 个请求。
- 体积构成：`index.html` 2.71 MB，其中 `atlas-json`（成就图标 1280×2112 JPEG 的 base64）**2.04 MB**；`collect-b64` 255 KB、`trinket-b64` 75 KB、`cards-b64` 25 KB、`data-json` 124 KB、`user-icons` 28 KB、`tainted-chars` 17 KB、`ipos-json` 17 KB、`pos-json` 11 KB；样式/脚本/标记约 135 KB。
- 线上静态资源只有 `index.html`：`/sw.js`、`/pwa/manifest.json`、PWA 图标请求都返回 HTML 回退页（text/html 2.9 MB）。原因：`scripts/build.mjs` 把 `public/` 复制到 `build/public/`，而 `<link rel="manifest" href="pwa/manifest.json">` 与 `navigator.serviceWorker.register('sw.js')` 都假定资源在站点根目录。结果 PWA 失效、service worker 从未注册成功。
- 卡片图标全部靠运行时 `canvas.drawImage + toDataURL` 生成 dataURL 再写入 DOM（成就图标 641 个、奖励图标 436 个），会同步卡住主线程。
- 全部 wiki 跳转都是 `target="_blank"`。从「添加到主屏幕」的 PWA（manifest `display: standalone`，已实测是独立窗口）打开 wiki 后，独立窗口栈里没有上一页，iOS 右滑自然退出到系统桌面 —— 这正是 iOS 体验差的根因之一。
- `https://isaac.huijiwiki.com` 响应头含 `X-Frame-Options: SAMEORIGIN`，**不能**用 iframe 内嵌 wiki 来实现「应用内打开」。
- 页面内嵌的 `collect-b64` 图集（实际 640×1280）与 `ipos-json` 坐标已经覆盖 721 个可放置道具、189 饰品，因此**道具与饰品不需要新图集**。
- 忏悔+ 成就 638–641 的图标已在现有成就图集中（638 网络+大便＝游玩联机、639 金色大便＝通关联机、640 沙漏＝通关联机每日挑战、641 书＝「读它！」）；`POS` 已覆盖 1–641 全部坐标。

## 2. 加载速度优化

瓶颈已实测：首屏 7 s 中约 4.7 s 卡在下载 2.9 MB 的单文件 HTML（gzip 后 1.55 MB），其中 2.04 MB 是可无损压缩的成就图集 base64；剩余约 2 s 是主线程解析与 637 次 canvas 生成 dataURL。

### 2.1 图标图集移出 HTML，改为外部图片 + CSS 裁剪

- **完全移出，不做双份兜底**：页内 2.04 MB 的 `atlas-json`、255 KB 的 `collect-b64`、75 KB 的 `trinket-b64`、25 KB 的 `cards-b64` 全部删除，改为 `public/assets/` 下的图片（随首次加载并行下载，并被 service worker 缓存）。模拟移除后 HTML 原始体积 **2.75 MB → 332 KB**，gzip **1549 KB → 120 KB**。
- 成就图集：`atlas-ach.png` 用 **nearest-neighbor 缩到 40px/格**（800×1320）再编 **palette-PNG（256 色）**，实测 **372 KB**（原 base64 2.04 MB）；已与 64px 原图做 22 个图标并排放大对比，肉眼看不出差异（40px 实际显示 58px）。32px WebP（309 KB）在边缘像素处略软，作为备选；若追求最小体积可换 32px palette-PNG（249 KB）。
- 道具/饰品图集：`item-collect.webp`、`item-trinket.webp` 用**无损 WebP**（118 + 20 = **138 KB**），避免压缩噪点影响 32px 像素画。
- 卡牌图集：重建为 **`item-cards.webp`（20×5 格、32px，97 个 ID 全对位）**，来源为 Guru 精灵表 `909–1005`（大牌 1–22、扑克牌 23–31、空白/黑符文 40–41、特殊卡 42–54、倒大牌 56–77、红钥匙碎片/红桃Q/万用牌 78–80、魂石 81–97），约 30 KB；**修复 §1.5 的 22 个错位 ID**。
- 新增 `item-runes.webp`（8 格，32px，符文 32–39），约 8 KB；新增 `item-pills.webp`（10×5 格，32px，药效 0–49），约 10 KB。
- 页面 `<img>` 改为 `iconStyle(sheet, cell)` 返回 `background-image + background-position` 的裁剪 div（`background-size` 按图集实际宽度除以 32 倍放大）。成就图集为 40px 格，换算为 ×1.25 的显示尺寸；奖励图集为 32px 原尺寸。不再 `toDataURL`，**每次页面加载写入 DOM 的字符串从约 4 MB 降为 0**。
- `POS`（成就图集坐标）不变；道具/饰品沿用现有 `IPOS` 坐标、运行时换算成新图集的 `cell`；卡牌、符文、胶囊按新网格生成 `cell`。堕化角色头像（17 个内嵌 32px base64）体积小，保持内嵌。
- 加载策略：成就图集 `fetchpriority="high"` + preload（首屏必需）；其余图集（`item-*`，共约 186 KB）随首屏并行下载。

### 2.2 静态资源按根路径正确发布（同时修复 PWA/Service Worker）

现状：`build.mjs` 把 `public/` 复制成 `build/public/`，而页面用相对路径 `pwa/manifest.json`、`sw.js` 引用根路径资源，导致线上 `/sw.js`、`/pwa/*` 回退成 HTML。

- `build.mjs` 改为把 `public/` 的内容**平铺**到 `build/` 根（`sw.js`、`pwa/`、`assets/`、`data/`、`_headers`），与 index 里的相对路径一致；不移动仓库里的源文件，避免破坏现有目录约定。
- 新增 `public/_headers`（Cloudflare Pages 支持）：`/`、`/index.html` 使用 `Cache-Control: no-cache`（保证更新立即生效）；`/assets/*`、`/data/*.json` 使用 `Cache-Control: public, max-age=31536000, immutable`（文件名带内容哈希）。
- `sw.js` 改为：页面 network-first；静态资源/数据 cache-first；`CACHE_NAME` 随构建版本自增。注册逻辑改为 `navigator.serviceWorker.register('/sw.js')`。
- `index.html` 里的 `manifest`、图标、`sw.js` 路径统一改为 `/pwa/...`、`/sw.js` 绝对路径。

### 2.3 首屏渲染分片

- `renderAll()` 一次性为 9 个标签页插入 637 张卡片；改为只渲染当前标签页，其它面板在首次切换时惰性渲染（`dirty` 标记 + 原有 `renderAll()` 逻辑复用）。
- 图标不再在启动时同步生成；首屏卡片直接输出裁剪 div，无阻塞。

### 2.5 验收指标

- 4G 模拟下（Chrome DevTools），首屏可交互 < 2 s；整页传输量从 gzip 1.55 MB 降到约 0.65 MB（HTML gzip 120 KB + 图集 ~558 KB）。
- `/sw.js`、`/pwa/manifest.json` 返回 `application/javascript`、`application/json` 且可安装 PWA。
- 图鉴打开时不新增任何外部域名请求。
- 图标观感与现版无可见差异；**符文/胶囊/塔罗牌图标正确**（#89–#96 与图鉴对照）。

## 3. iOS「返回之前的浏览位置」（v1）

### 3.1 机制

- 每次从本应用点击 wiki 链接（成就标题、奖励内联链接、图鉴条目名称）时，`openWiki(url)` 先把浏览上下文写入本页 `sessionStorage['isaac_last_view']`：滚动位置、当前标签页、搜索词、筛选状态、若来自图鉴则记录图鉴滚动位置与筛选。
- wiki 链接地址统一带上 `?from=isaac`（灰机 wiki 会忽略未知查询参数）。实现上所有 `href="https://isaac.huijiwiki.com..."` 生成处统一换成 `openWiki`/带参助手，避免遗漏。
- 用户在 wiki 页面（iOS 独立窗口）无法修改第三方站点 UI，因此**在应用内**提供返回入口：
  - 应用每次 `pageshow`（包括 bfcache 恢复的 `event.persisted` 分支）时从 `sessionStorage` 恢复视图，并短暂显示「欢迎回来」提示。
  - 主界面顶栏新增「↩ 回到上次位置」按钮：只要 `sessionStorage` 有记录就可见，点击立即恢复滚动/标签页/筛选。
  - 应用内打开 wiki 的方式改为优先「同标签跳转」而不是 `target=_blank`：这样 iOS 浏览器（Safari）里左滑即返回上一页并自动恢复视图；在已安装 PWA 的独立窗口里也至少保证返回后点一次「回到上次位置」即可恢复。
- 非 PWA 浏览器环境额外增强：`history.pushState` 记录应用内位置，`popstate` 时恢复。

### 3.2 v1 范围

- 本版交付上述机制，供用户实测；**暂不做**：多级返回栈、跨会话恢复（关闭 PWA 后重开）、wiki 内二次跳转后的精确回溯。

### 3.3 验收

- Safari（含独立窗口与普通标签页）下：查看成就 → 点 wiki → 返回后位置恢复。
- 图鉴 → 点道具名称 → wiki → 返回后图鉴仍停在同一道具、滚动与筛选状态不变。

## 4. 道具图鉴悬浮窗

### 4.1 入口与布局

- 右侧可拖动圆形/胶囊按钮「道具」（`touch-action: none`，Pointer Events），松手后吸边，位置存 `localStorage`；拖动距离小于阈值时视为点击打开图鉴。
- 点击打开全屏（移动端）/ 右侧抽屉（桌面端）的图鉴面板。
- 顶部：搜索框 + 排序切换（首字母 / ID）+ 品质筛选。
- 分类用**四个独立标签页**区分，与普通道具分开（用户明确要求「胶囊等分类与普通道具区分，用不同标签放置」）：
  1. **道具**（被动/主动/跟班，709 条）
  2. **饰品**（187 条）
  3. **胶囊**（50 条药效）
  4. **卡牌·符文**（97 条：大牌、扑克牌、符文、特殊卡、倒大牌、魂石）
- 原先设计的「拾取物」组（金胶囊、金福袋、箱子等）取消，不进图鉴；这些成就在主页仍按现状处理。
- 品质筛选只在「道具」「饰品」页出现；胶囊/卡牌页隐藏该筛选。

### 4.2 数据模型（构建期生成）

`scripts/gen-codex.mjs` 生成 `public/data/codex.json`：

```json
      "id": 488,
      "kind": "collectible",        // collectible | trinket | card | pill

      "en": "Metronome",

      "pools": ["treasure", "greedShop", "craneGame"],
      "tags": ["offensive"],
      "desc": "使用后，在当前房间中获得一个随机道具的效果……",

      "py": "jiepaiqi",             // 构建期拼音（无声调）
      "ini": "jpq",                 // 首字母

    }
  ],
  "aliases": { "小汽车": [488], "猫爪": [160], "妈刀": [228] }
}
```

- 名称（中文）：EID `descriptions/names/zh_cn.lua`（道具 C1–C732 中 721 个有名称 / 饰品 189 / 卡牌 97 / 胶囊 51）。11 个不可拾取的特殊 ID（43、61、235、587、613、620、630、648、662、666、718）名称表为空，不进图鉴；搜索这些 ID 时提示「该 ID 无对应可拾取道具」。C656（DAMOCLES_PASSIVE）名称/描述复用 C577，图标用 656 的贴图。

### 4.4 排序与首字母索引条

- 排序切换：**首字母**（默认）与 **ID**。
- 「首字母」：按中文名拼音首字母分组，顺序 `0-9` → `A`–`Z` → `#`（以符号开头的名称）；组内按完整拼音、再按 ID 升序。右侧竖向索引条显示当前分类实际存在的字母，点击/按住滑动跳转到该组；滚动时高亮当前字母。
- 「ID」：按 ID 排序（升序/降序沿用现有默认：降序），**不显示右侧索引条**（用户明确要求）。
- 索引条与滚动容器联动：点击字母 = 平滑滚动到该组标题；滚动时用 IntersectionObserver 高亮最近组。
- 排序/筛选状态存 `sessionStorage`，与 §3 的返回恢复共用。

### 4.6 搜索（精确查找 / 模糊搜索）

搜索框输入后，结果区分两栏展示：

**第一栏「精确查找」**：输入的文字作为**连续子串**出现在名称中，或输入是纯数字且等于某个 ID。

- 道具/饰品/卡牌/胶囊：命中中文名、英文名（不区分大小写）、ID。
- 成就（主页面搜索）：命中成就 `title`、`cond`、`en`、奖励名。
- 展示：道具/饰品等显示「图标 + 名称 + (ID)」；成就显示「图标 + 成就名称」。点击名称跳 wiki（带 §3 返回）。

**第二栏「模糊搜索」**：按用户要求，**别名、同音字、错别字一律归入这一栏**；以下任一命中即入选，**只显示图标网格**（不显示名称，由用户凭图案判断），点击图标弹出该条目详情。

1. 别名（用户表格中的别称，含「名称中不连续出现」的缩写：猫爪→嗝屁猫的爪子、妈刀→妈妈的菜刀）。
2. 子序列匹配：查询字符按顺序出现在名称中（不要求连续），如「猫爪」「妈刀」；查询字符数 ≥2 时启用，避免单字噪声。
3. 拼音：完整拼音（`jiepaiqi`）、首字母（`jpq`）、带混输（如 `jiepq`）。
4. 同音字/错字：构建期为名称中出现的每个汉字生成「字→拼音」表；运行时把查询字按拼音归一后比对名称拼音；再叠加一次编辑距离 ≤1 的比较，覆盖错字。

同一条目若同时满足精确与模糊，**只在精确栏出现**（去重）。无结果时提示「没有找到，试试别名或拼音」。

### 4.7 别名表

#### 4.7.1 数据来源
用户桌面表格 `道具别称对照表.xlsx`（Sheet1，156 行：`id | 道具实际名称 | 别称`，共 179 个去重别称），构建期解析为 `aliases` 映射（一个别名可对应多个 ID，一个 ID 可有多个别名）。

#### 4.7.2 解析规则（按优先级）
表格的 `id` 列混用了道具/饰品/卡牌的 ID 空间（例如 4 同时是「柯吉猫的头 C4」与「损坏的遥控器 T4」，169 同时是「巨人独眼 C169」与「儿童涂鸦 T169」），因此**不直接按 ID 挂接**，而是：

1. **名称精确匹配**：把表格的「道具实际名称」在全部四个名称表（道具 / 饰品 / 卡牌 / 胶囊）中精确查找，命中唯一则直接挂接。156 行里 126 行走这条（122 道具、3 饰品、1 卡牌）。「彼列之书」在名称表中同时存在 C34 与 C59，按表格 ID 定为 C34。
2. **ID 兜底**：名称未精确命中时，按 ID 到道具表取名称，并与表格名称做「包含/缩写」校验（如 191 三美元 ↔ C191 3美元纸币、81 死猫 ↔ C81 嗝屁猫、124 怪异蘑菇 ↔ C120 怪异蘑菇(小)）。29 行走这条，全部校验通过；表格名称仅作记录，图鉴显示以 EID 官方名为准。
3. **自我指代**：别称与名称相同（仅 1 行：246 蓝地图）直接忽略。
4. **重复别名**：同一 ID 的多个别称合并（狗头/破传 等）；别称恰好等于某个官方名（五芒星→C51、小蘑菇→C71、萌死戳的牙→C86）时保留，搜索时精确栏本来就会命中该名，不产生歧义。
5. 仍有未解析的行（当前为 0）时，构建脚本报错并列出，不静默跳过。

#### 4.7.3 已核对、无需用户确认的项
